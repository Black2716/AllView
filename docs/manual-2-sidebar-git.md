# 手册二：DSH 侧边栏（better-sidebar）的 Git 怎么用（AllView）

> 对象：DSH 右侧边栏插件 **dsh-better-sidebar 0.30.1** 的 `Git` 标签页（不是 VS Code）  
> 项目目录：`<本地项目目录>`（示例 `E:/code/project/vibe/AllView`）  
> 前置：已按手册一第 0 章配好身份与凭据。侧边栏不自己管凭据，它调用**同一个系统 git**，所以凭据、`.git/config` 完全共用。

一句话原则：**日常提交、推送、放弃改动点面板；打 tag、逐块暂存、强制推送、解分叉回终端**（原因见第 8 节）。

---

## 1. 打开 Git 标签页

**1.1 先让会话的工作目录落在项目根**

侧边栏的 Git 作用域是**当前会话的 cwd**。先在对话里把工作目录切到项目根（含 `settings.gradle.kts` 的那层）：

```
working_directory(cd: "E:/code/project/vibe/AllView")
```

cwd 不在仓库里时，面板只显示一句 `当前目录不是 git 仓库`。

**1.2 打开面板**

右侧边栏顶部是标签栏。点 **`Git`** 标签（图标是一支分支符号）。它的副标题是「Git 变更与本轮文件改动，双视角合一」。

**1.2b 标签内有两个视角 + 一个区块**

| 位置 | 中文标题 | 内容 |
|---|---|---|
| 视角 1 | `Git` | 真正的 git 工作区：提交框 + 三个分组 + 底部分支/同步（**日常就用这个**） |
| 视角 2 | `本轮文件` | 本会话里 Agent 读过/写过哪些文件（**不是 git**，别混） |
| 区块（在 Git 视角下方） | `提交图` | 提交历史图，可折叠，带「所有分支」筛选 |

> 「本轮文件」列的是 Agent 的读写记录（读取/写入/编辑/执行中）。提交、推送、放弃改动**只在 `Git` 视角**做。

**1.3 面板纵向布局**

```
┌────────────────────────────────────┐
│ 更改                        ✓ ↻ ⋯  │  ← 标题行：提交 / 刷新 / 更多操作
├────────────────────────────────────┤
│ [Message (Ctrl+Enter to commit on   │  ← 提交信息框
│  "main")]                     ✨   │     ✨=用模型生成提交信息
├────────────────────────────────────┤
│ 合并更改            (冲突时才出现)   │
│ 暂存的更改                          │
│ 更改                                │
├────────────────────────────────────┤
│ 提交图                        ⌄     │
├────────────────────────────────────┤
│ ⎇ main*+          同步更改 0↓ 1↑    │  ← 底部：分支 / 同步
└────────────────────────────────────┘
```

## 2. 看懂分组 / 标记 / 底部状态

**2.1 三个分组**

| 分组 | 何时出现 | 含义 | 终端等价 |
|---|---|---|---|
| **合并更改** | 只在 pull/merge 有冲突时出现，标题后带 `!` | 冲突中的文件，**必须先解决才能提交** | `UU`/`AA` |
| **暂存的更改** | 有已暂存内容时 | 下次提交会带上 | `git diff --cached` |
| **更改** | 有未暂存内容时 | 还没进这次提交 | `git diff` |

工作区没有任何改动时，面板显示 `工作区没有变更`。

**2.2 行右侧的字母（XY 状态）**

沿用 git porcelain 的两位标记，`git status -sb` 里看到什么，这里就是什么：

| 显示 | 含义 |
|---|---|
| `M` | 已修改 |
| `A` | 新增（已暂存） |
| `U` / `?` | 未跟踪的新文件 |
| `D` | 删除 |
| `R` | 重命名 |
| `!` | 冲突 |

同一个文件如果先暂存又继续改，会**同时**出现在「暂存的更改」和「更改」两个分组里，各自显示自己那一侧的增删行数（面板刻意不把两侧数字相加）。

**2.3 底部两个东西**

**(a) 分支按钮** `⎇ main*+`

```
main        当前分支
*           有未暂存改动
+           有已暂存改动
!           正在 merge/rebase 或有冲突
游离 HEAD    处于 detached HEAD
```

点它弹出分支列表，选中即 `git checkout <分支>`。切换失败会在面板内显示 `切换分支失败`。

**(b) 同步按钮** `同步更改: origin/main · 0↓ 1↑`

```
0↓  远端没有新提交
1↑  本地领先 1 个提交（可推）
悬停显示完整标题：同步更改: origin/main · 0↓ 1↑
```

对应终端 `git status -sb` 的 `## main...origin/main [ahead 1]`。

按钮上的文字也可能是：

| 文字 | 含义 |
|---|---|
| `未设置上游` | 分支没有 upstream，先 `git push -u origin main` |
| `同步不可用` | 还没拿到 ahead/behind（等刷新或 detached） |
| `游离 HEAD` | detached，不能同步 |

**2.4 看某个文件改了什么**

点文件行 → 下方打开 diff 预览（灰底「未暂存」/「暂存」徽标标明这一侧）。右上角 `在独立页签中打开` 可把 diff 摊成整页。

预览里有 `差异` / `内容` 两个子页签：前者是 diff，后者是文件当前全文。

## 3. 暂存与取消暂存

**3.1 单个文件**

```
鼠标移到「更改」里的某一行 → 行尾出现 +  → 点它 = git add -- <path>
鼠标移到「暂存的更改」某一行 → 行尾出现 −  → 点它 = git reset -- <path>
```

**3.2 整组**

```
「更改」分组标题右侧  +  = 全部暂存
「暂存的更改」分组标题右侧 − = 全部取消暂存
```

**3.3 右键菜单（比按钮多几项）**

在文件行上右键，菜单项：

| 菜单项 | 作用 | 终端等价 |
|---|---|---|
| 打开编辑器 | 在侧边栏编辑器里打开该文件 | — |
| 暂存 / 取消暂存 | 同 `+` / `−` | `git add -- <path>` / `git reset -- <path>` |
| **放弃更改** | 丢弃该文件**工作区**的改动（红色危险项，会弹确认框） | `git checkout -- <path>` |
| 复制相对路径 / 绝对路径 | 取路径 | — |

> 「放弃更改」只对**已跟踪**文件出现（未跟踪的新文件没有这一项，要删就自己删）。它**不可恢复**，确认框文字是「将丢弃「{path}」的工作区修改（不可恢复）」。

**3.4 面板做不到的：逐块/逐行暂存**

侧边栏的暂存粒度是**整个文件**（`git add -A -- <path>`），没有 hunk 级操作。只想提交一个文件里的一部分 → 回终端 `git add -p`（手册一 2.1）。

## 4. 写提交信息并提交

**4.1 标准流程**

```
1. 点 + 把要提交的文件放进「暂存的更改」
2. 在提交信息框输入信息（占位符会提示当前分支和快捷键）
3. Ctrl+Enter（Mac 是 Cmd+Enter）提交
   也可以点标题行的 ✓ 按钮
```

底层就是 `git commit -m "<你写的信息>"`，**不会**动你的 `user.name` / `user.email`。

**4.2 提交按钮什么时候是灰的**

必须同时满足才可提交：

- 当前目录是 git 仓库
- 「暂存的更改」里至少有 1 个文件（**只改不暂存不能提交**）
- 提交信息框非空
- 没有未解决的冲突（「合并更改」区为空）
- 没有正在进行的 git 操作

**4.3 用模型生成提交信息**

```
点提交框右侧的 ✨ 按钮   或   在框里按 Ctrl+G
```

面板会把待提交的 diff（截断到约 12KB）发给模型，生成一条中文/英文提交信息填进框里。**生成后务必自己读一遍再提交**——模型没看过你的意图。

可在标签的设置里指定用哪个模型（`提交信息生成模型`，默认「跟随当前对话」）。

> 面板**没有** amend、没有「撤销上次提交」。这两件事回终端（手册一 7.4、7.3）。

## 5. 推送、拉取、同步

**5.1 三个入口**

| 入口 | 底层命令 | 说明 |
|---|---|---|
| 底部 **同步更改** 按钮 | `git pull --ff-only` 然后 `git push` | 先拉后推，一步到位 |
| `⋯` → **拉取** | `git pull --ff-only` | 只拉 |
| `⋯` → **推送** | `git push` | 只推，不带参数（依赖已有 upstream） |

`⋯` 菜单（标题行最右）内容：`拉取`、`推送`，以及（满足条件时）`仓库` 子菜单、`工作树` 子菜单。

**5.2 点哪个**

```
底部显示 0↓ 1↑   → 点同步（或 ⋯→推送）
底部显示 3↓ 0↑   → 点同步（或 ⋯→拉取）
底部显示 2↓ 4↑   → 点同步会先 pull 再 push；pull 是 --ff-only，分叉会失败 → 见 5.4
底部显示 0↓ 0↑   → 已同步，无需操作
```

**5.3 成功与失败的样子**

成功后底部数字归零、面板自动刷新。失败会在面板底部弹出红色提示条：`推送失败` / `拉取失败` / `切换分支失败`，点右侧 `×` 关掉。

**5.4 本仓库常见的三个失败**

| 提示 | 原因 | 处理 |
|---|---|---|
| 推送失败 + `Failed to connect to github.com:443` | DNS 污染（本仓库特有） | 手册一 9.1；侧边栏用同一份 `.git/config`，终端修好后这里立刻恢复 |
| 推送失败 + `could not read Username` / 要凭据 | 没配凭据 | 手册一 9.3（`gh auth login` 或 wincred + PAT） |
| 推送失败 + `without workflow scope` | token 缺 `workflow` 权限 | 手册一 9.2 |
| 拉取失败 + `Not possible to fast-forward` | 本地和远端**分叉**了，`--ff-only` 拒绝合并 | **回终端**：`git pull --rebase`（手册一 4.1） |

> 侧边栏的 pull 是 `--ff-only`，这是刻意设计：无界面环境不打开合并编辑器。分叉了必须自己在终端 rebase。

## 6. 分支切换与提交图

**6.1 切分支**

点底部 `⎇ main` → 列表里选目标分支。等价 `git checkout --end-of-options <分支>`。

有未提交改动时 git 可能拒绝（会覆盖你的改动）→ 先提交或先 stash（stash 只能终端）。

**6.2 提交图**

面板里 `提交图` 区块，点标题展开：

| 元素 | 作用 |
|---|---|
| `所有分支` | 切换为只显示当前分支的历史 |
| `分支筛选` | 只看某个分支 |
| 提交行 | 点开看该提交的详情与文件 diff |
| `提交详情` / `父提交` | 选中提交的元信息 |
| `加载更多` | 分页拉更多历史 |

提交行右键菜单：

| 菜单项 | 等效命令 |
|---|---|
| 查看提交差异 | `git show <hash>` |
| 复制短哈希 / 完整哈希 / 提交信息 | — |
| **还原此提交** | `git revert --no-edit <hash>`（**新建**一个反向提交，不破坏历史） |
| **捡取此提交** | `git cherry-pick <hash>` |

「还原此提交」是改**已推送**内容的安全做法：它产生新提交，事后正常推送即可，不需要强推。

## 7. 撤销

| 想撤销什么 | 在哪做 | 操作 | 终端等价 |
|---|---|---|---|
| 某文件未暂存的改动 | 面板 | 右键该行 → 放弃更改 | `git checkout -- <path>` |
| 暂存状态（改动保留） | 面板 | 点 `−` 或分组标题 `−` | `git reset -- <path>` |
| 刚提交、还没 push | **终端** | — | `git reset --soft HEAD~1` |
| 已 push 的某次提交 | 面板（提交图） | 右键 → 还原此提交 | `git revert --no-edit <hash>` |
| reset --hard 搞砸了 | **终端** | — | `git reflog` + `git reset --hard <hash>` |

> 面板没有「撤销上次提交」这个按钮，别看错成 ✓。

## 8. 哪些点面板，哪些必须回终端

**8.1 面板就够（日常 90%）**

| 操作 | 位置 |
|---|---|
| 看哪些文件改了、增删多少行 | Git 视角三个分组 |
| 读某个文件的 diff | 点文件行 → 下方 diff 预览 |
| 整文件暂存/取消暂存 | 行尾 `+` / `−` |
| 写信息、提交 | 提交框 + Ctrl+Enter / ✓ |
| 生成提交信息草稿 | ✨ / Ctrl+G |
| 推送、拉取、同步 | 底部同步按钮、`⋯` 菜单 |
| 放弃某文件改动 | 右键 → 放弃更改 |
| 切分支 | 底部分支按钮 |
| 看历史、还原某提交 | 提交图 + 右键 |

**8.2 必须回终端**

| 操作 | 为什么面板不行 | 命令 |
|---|---|---|
| **打 tag / 推 tag** | 面板没有 tag 功能 | `git tag -a v1.2.0 -m "..."` + `git push origin v1.2.0` |
| **上传 Release 资产** | 属 GitHub 平台功能 | `gh release create/upload`（手册一第 6 章） |
| **逐块暂存** | 只有整文件粒度 | `git add -p` |
| **amend 提交 / 撤销上次提交** | 无对应按钮 | `git commit --amend` / `git reset --soft HEAD~1` |
| **强推** | 无入口 | `git push --force-with-lease` |
| **分叉后的 pull** | 只做 `--ff-only` | `git pull --rebase` |
| **stash** | 无入口 | `git stash` / `git stash pop` |
| **改 http.curloptResolve 等配置** | 属仓库配置 | `git config --local ...` |
| **reflog 找回** | 无入口 | `git reflog` |

**8.3 就地开终端**

侧边栏自带 `终端` 标签页（真实 shell，xterm + pty）。切到它就能跑上面所有命令，不用离开 DSH。

终端默认 shell 若不是 Git Bash，`export`、`/e/` 这类写法会不认；手册一里的命令按 Git Bash 写，遇到报错就按 POSIX 改或用完整 `E:/` 路径。

## 9. 验收：用面板走一遍「改 → 提交 → 推」

```
① 侧边栏终端里确认起点
   git status -sb          →  ## main...origin/main

② 随便改一行，例如 README 末尾加一个空格再删掉，或改 demo.md 里一个词

③ Git 视角：出现在「更改」分组，行尾显示 +  和增删行数

④ 点该行的 +  → 移到「暂存的更改」

⑤ 提交框写：修复：demo.md 措辞  →  Ctrl+Enter
   期望：底部出现新提交，底部数字变成 0↓ 1↑

⑥ 点底部「同步更改」
   期望：数字归零；浏览器打开仓库能看到新提交

⑦ 复核
   终端：git log --oneline -1   →  与面板/网页一致
   curl -sIL https://github.com/Black2716/AllView/commits/main | head -1  →  200
```

走到 ⑥ 成功、⑦ 一致，就算不求助任何人完成了「提交 → push」。

## 10. 附录：最常用 10 条命令速查

| # | 命令 | 干什么 | 面板能做吗 |
|---|---|---|---|
| 1 | `git status -sb` | 看改动与领先/落后 | ✅ 分组 + 底部数字 |
| 2 | `git diff` | 看具体改了哪几行 | ✅ 点文件行 |
| 3 | `git add -A` | 暂存全部 | ✅ 分组标题 `+` |
| 4 | `git commit -m "说明"` | 提交 | ✅ 提交框 Ctrl+Enter |
| 5 | `git push` | 推上去 | ✅ `⋯→推送` |
| 6 | `git pull --rebase` | 同步（分叉时） | ❌ 面板只做 `--ff-only` |
| 7 | `git log --oneline -5` | 看最近提交 | ✅ 提交图 |
| 8 | `git restore <文件>` | 丢弃未提交改动 | ✅ 右键→放弃更改 |
| 9 | `git push origin v1.2.0` | 推 tag（发版） | ❌ 无 tag 功能 |
| 10 | `gh release upload v1.2.0 <apk> --clobber` | 换 Release 里的 APK | ❌ 平台功能 |

## 11. 附录：「改完代码 → 发布新版本」完整流程（标注在哪做）

```
① 起点干净
   面板：Git 视角 → 工作区没有变更；底部 0↓ 0↑
   终端：git status -sb  →  ## main...origin/main

② 同步（有 ↓ 才需要）
   面板：底部「同步更改」
   分叉时改终端：git pull --rebase

③ 改代码

④ 本地验证（终端）
   ./gradlew :app:testDebugUnitTest
   ./gradlew :app:assembleRelease

⑤ 暂存 + 提交（面板）
   确认「暂存的更改」里没有 dist/、app/build/、local.properties
   ✨ 可选生成信息 → 自己改一遍 → Ctrl+Enter

⑥ 推送（面板）
   底部「同步更改」或 ⋯→推送
   期望：0↓ 0↑

⑦ 打 tag 并推 tag（终端，必须）
   VERSION=1.2.0
   git tag -a v$VERSION -m "AllView $VERSION"
   git push origin v$VERSION

⑧ 备 APK（终端；dist/ 被忽略，不进版本历史）
   mkdir -p dist
   cp app/build/outputs/apk/release/app-release.apk dist/AllView-$VERSION-release.apk

⑨ 传 Release（终端，必须）
   gh release create v$VERSION "dist/AllView-$VERSION-release.apk" \
     --title "AllView $VERSION" --notes "本次改动摘要"

⑩ 验收（终端）
   curl -sIL "https://github.com/Black2716/AllView/releases/download/v$VERSION/AllView-$VERSION-release.apk" \
     | grep -iE 'HTTP/|content-length'

⑪ CI
   浏览器：https://github.com/Black2716/AllView/actions  → 最新一次绿色 ✓
```

只想改代码不发版：做到 **⑥** 结束。
