# AllView UI 改造方案

> **实施状态（2026-11-22）**：档位一 5 项 + 档位二 3 项 + 档位三 3 项已全部完成并实测；
> release 1,241,595 → **1,256,959 字节（+15 KB）**，55 个单测全绿，**0 新增依赖**。
> 本方案只谈视觉与交互，不动解析、公式、搜索、目录的既有逻辑。

---

## 一、诊断：「丑」到底丑在哪

不是主观感受，下面每条都能在源码里指到具体位置。

### 1. 底部栏是六个文字胶囊挤在一起

`ReaderScreen.kt` 的 `ReaderBottomBar`：

```
[A-] [A+] [目录] [搜索] [设置]        [换文件]
```

六个控件全是同一个 `PillButton`（13sp 纯文字、`surfaceVariant` 底色、8dp 圆角），**没有主次、没有图标、没有分组语义**。
`A-` / `A+` 拿字母当按钮名，是典型的「还没设计过」。
按钮内边距 `horizontal = 12.dp, vertical = 7.dp`、字号 13sp，整栏实测约 54dp 高，占了阅读区约 8% 的高度，却只提供六个文字。

### 2. 全项目零图标

`app/build.gradle.kts` 只引了 `material3`，没有 `material-icons-extended`，`grep Icons.` 结果为空；
整个 `ui/` 层（2,088 行）**`IconButton` 使用次数为 0**。
于是目录、搜索、设置、换文件、关闭、删除全部用汉字或 `×` `§` 充当图标。

### 3. 配色只定义了 18 个角色，缺 M3 关键项

`Theme.kt` 只覆盖 `primary / background / surface / surfaceVariant / outline` 及其 `on*`。
**缺** `secondary`、`tertiary`、`surfaceContainer*`、`error`、`scrim`、`inverseSurface`。
后果：`Slider`、`OutlinedTextField`、`ModalBottomSheet` 的拖拽手柄会用 M3 默认值，和纸感配色打架——设置里的滑杆就是这样，蓝色滑块配紫色轨道。

### 4. 三种面板、三套外观

| 面板 | 实现 | 问题 |
|---|---|---|
| 目录 `TocSheet` | `ModalBottomSheet` | 正常 |
| 搜索 `SearchSheet` | `ModalBottomSheet` | 正常 |
| 设置 `SettingsSheet` | **手写 `Box` + `Color.Black.copy(alpha = 0.35f)` 遮罩** | 无拖拽手柄、无圆角动画、遮罩浓度和另外两个不一致、点击外部才关 |

同一个 App 里三种面板观感，是「丑」最直接的来源之一。

### 5. 字号与间距没有体系

硬编码统计：

| 字号 | 出现次数 |
|---|---|
| 14.sp | 7 |
| 13.sp | 7 |
| 12.sp | 4 |
| 16 / 15 / 11 / 30.sp | 各 3 / 3 / 2 / 1 |

间距 `dp` 出现 8/10/12/6/1/2/20/9/18/16 等十余种，**不是 4dp 栅格**。
圆角有 **7 种**：1 / 2 / 6 / 8 / 9 / 10 / 18 dp（`RoundedCornerShape(8.dp)` 一个就用了 8 次，其余各 1~2 次）。

### 6. 标题靠字号硬缩放，不是排版层级

`HeadingView` 用 `1.72 / 1.42 / 1.20 / 1.06 / 0.98 / 0.92` 六档倍率乘基准字号。
问题是**只有字号在变**：行高比例、字重、段前距、颜色都不随层级变化，H3 和 H4 视觉上几乎分不开。

### 7. 没有动效

顶栏是 `if (showBar) { TopBar(...) }` —— 硬切出现、硬切消失。面板打开、跳转滚动全是瞬变（跳转用了 `animateScrollToItem` 是唯一例外）。

## 二、设计方案

### 2.0 设计语言一句话

**纸感阅读器：中性色做底、一种强调色、无衬线正文、信息靠层级不靠装饰。**
据此定三条硬规则：

1. **颜色只用得上一处强调**——链接、当前项、主按钮。其余靠灰阶与留白分层次。
2. **所有可点元素必须有图标**，文字只作补充。
3. **间距 4dp 栅格、圆角只用 3 档**（6 / 12 / 全圆）。

### 2.1 设计令牌（新增 `ui/Design.kt`，约 120 行）

```kotlin
object Sp {                      // 4dp 栅格，只留 6 档
    val xs = 4.dp; val s = 8.dp; val m = 12.dp
    val l = 16.dp; val xl = 24.dp; val xxl = 32.dp
}
object Radius {                  // 只留 3 档
    val s = 6.dp; val m = 12.dp; val pill = 999.dp
}
object Type {                    // 6 档字阶，替代散落的 sp 硬编码
    val label = 11.sp            // 块号、图注
    val caption = 12.sp          // 次要说明
    val body = 13.sp             // 面板内文字
    val bodyL = 14.sp            // 列表主文字
    val title = 16.sp            // 面板标题
    val display = 28.sp          // 空态主标题
}
```

### 2.2 配色补全（改 `Theme.kt`，约 40 行）

补齐 M3 组件真正会读的角色，纸感不变：

```
secondary        = 强调色的去饱和版（分类、次级动作）
surfaceContainer = 面板/卡片底（比 surfaceVariant 更贴合 M3 3.x）
error            = 用于「放弃更改」「删除」等破坏性操作
scrim            = Color.Black.copy(alpha = 0.32f)  // 统一遮罩浓度
inverseSurface   = 深色 toast/提示
```

浅色仍维持 `#FCFCFA` 纸白，深色维持 `#111315`，**不动已验证的对比度**。

### 2.3 图标（关键取舍）

两条路，二选一：

| 方案 | 体积 | 工作量 | 评价 |
|---|---|---|---|
| A. 引 `material-icons-extended` | R8 后约 **+25~60 KB**（只保留被引用的图标） | 几乎为零，直接用 `Icons.Outlined.*` | 图标完整、风格统一，但新增依赖 |
| B. 手写 vector（6~10 个） | 约 **+6 KB** | 每个约 15 行，共约 1.5 小时 | 零依赖，但以后每加一个功能都要画一个 |

**推荐 B**：本轮只需要 8 个图标（目录 / 搜索 / 设置 / 文件 / 关闭 / 字号减小 / 字号增大 / 勾选），
手写一次就够用很久，和「1 MB 阅读器」的取向一致。若后续要上大量图标再切 A。

### 2.4 底部栏重做（改 `ReaderScreen.kt`，约 80 行）

从「六个文字胶囊」改成「一个主操作 + 三个图标 + 字号浮层」：

```
现在：  [A-] [A+] [目录] [搜索] [设置]           [换文件]

改后：   ┌──────────────────────────────────────────┐
        │  ≡目录    🔍搜索    Aa字号    ⋯更多      │   ← 四个图标，等距
        └──────────────────────────────────────────┘
                    ↑ 点 Aa 弹出字号浮层（不是按钮对）
```

- **字号调节**从两个常驻按钮改成**点一次「Aa」弹出小浮层**：`A-  ━━━  A+`，拖动即时生效，松手收起。
  理由：调字号是低频操作（一本书调 1~2 次），不值得常驻两个按钮位。
- **换文件**收进「⋯更多」（低频），让主栏从 6 项降到 4 项，密度立刻下来。
- 图标 24dp，点击区 48dp（`minimumInteractiveComponentSize`），触摸友好。
- 栏高从 56dp 降到 **52dp**，底板用 `surfaceContainer` + 顶部 1dp `outlineVariant` 发丝线。

### 2.5 阅读区排版（改 `MdRenderer.kt`，约 60 行）

标题从「只缩字号」改成**字号 + 行高 + 字重 + 段前距四件套**：

| 级别 | 字号 | 行高 | 字重 | 段前 | 段后 | 额外 |
|---|---|---|---|---|---|---|
| H1 | 1.75× | 1.25 | Bold | 28 | 12 | 底部 40dp 强调色短横 |
| H2 | 1.40× | 1.30 | Semibold | 24 | 10 | 底部 1dp 发丝线（通栏） |
| H3 | 1.18× | 1.35 | Semibold | 18 | 8 | — |
| H4 | 1.05× | 1.40 | Medium | 14 | 6 | — |
| H5/H6 | 1.00× | 1.45 | Medium | 12 | 4 | 颜色降为 onSurfaceVariant |

H2 加通栏发丝线是关键改动——现在 H2 和 H3 只差 0.22 倍字号，加了线立刻分得开。

其余微调：

- 代码块圆角 8→12，内边距 12→**14**，语言标签改成右上角小胶囊（现在在左上角占一整行）。
- 引用块竖线从 3dp 加粗到 **4dp**，圆角 2dp，左侧内边距 12→**16**。
- 表格首行底色从 `surfaceVariant` 改为 `surfaceContainer`，行分隔线透明度 0.5→**0.35**（现在太重）。
- 图片圆角 8→12，图注居中且降到 `Type.label`。

### 2.6 设置面板统一（改 `SettingsSheet.kt`，约 100 行）

**直接换成 `ModalBottomSheet`**，和目录/搜索统一：

```
┌─────────────────────────────────────┐
│            ━━  (拖拽手柄)            │
│  显示                                │
│  ┌───────────────────────────────┐  │
│  │ 字号              Aa 17        │  │
│  │ A────────●────────────A        │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 外观                            │  │
│  │ [跟随系统] [浅色] [深色]        │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

- 分区标题（`显示`）+ 卡片式分组，替代现在平铺的「字号 / 外观 / 完成」。
- 滑块两端放 `A` 小图标（小/大），比现在光秃秃一条轨道直观。
- 删掉底部的「完成」按钮——`ModalBottomSheet` 下滑即关，多一个按钮是多余的。

### 2.7 动效（改 3 处，约 25 行）

| 位置 | 现在 | 改后 |
|---|---|---|
| 顶栏显隐 | `if (showBar)` 硬切 | `AnimatedVisibility` + `fadeIn/out(150ms)` + `slideInVertically` |
| 面板打开 | M3 默认 | M3 默认即可，无需改 |
| 空态 → 文档 | 硬切 | `Crossfade(200ms)` |

只加这三处，不做花哨动画——阅读器的动效应该感觉不到。

## 四、优先级与推荐

### 4.1 为什么这个顺序

「丑」的体感按贡献度排序：

1. **底部栏**占屏 10%，六个文字胶囊是最高频的视觉接触 → 必须最先改
2. **零图标**让所有控件都像半成品 → 和底部栏一起改，一次到位
3. **设置面板**是第三种外观，割裂感最强 → 换个组件就好，成本极低
4. **配色缺角色**导致 M3 组件「串味」→ 30 分钟补完
5. 排版细节（标题层级）影响的是「专不专业」，不是「丑不丑」→ 第二档

### 4.2 推荐先落地：档位一的 1→2→3→4（约 6 小时）

这四项做完，界面从「能用的原型」变成「有设计感的工具」，且**不动任何阅读逻辑**。

### 4.3 第一步实现步骤（可直接照做）

**Step 1（1 小时）· 建立令牌**

```
1. 新建 ui/Design.kt：Sp / Radius / Type 三个 object（见 2.1）
2. 不改任何调用点，先让文件就位
3. 编译确认通过（此时零行为变化）
```

验收：`./gradlew :app:assembleDebug` 通过，55 个单测全绿（纯新增文件，不可能影响测试）。

**Step 2（30 分钟）· 补配色**

```
1. Theme.kt 的 LightColors / DarkColors 各补 5 个角色
2. 打开设置面板看 Slider 是不是不再串色
```

验收：设置面板的滑杆、搜索面板的输入框、三个 `ModalBottomSheet` 的拖拽手柄，颜色都和主色一致。

**Step 3（1.5 小时）· 手写图标**

```
ic_toc.xml        三层横线（目录）
ic_search.xml     放大镜
ic_settings.xml   齿轮（可简化为三个圆点+外圈）
ic_font.xml       "Aa" 路径（字号）
ic_more.xml       三个点
ic_close.xml      叉
ic_minus.xml / ic_plus.xml
```

全部 24×24 viewport，`android:tint="?attr/colorControlNormal"` 交给 Compose 着色。

验收：8 个 vector 都能在 Preview 里正常显示，无变形。

**Step 4（3 小时）· 底部栏重做**

```
1. ReaderBottomBar 改成 Row + 4 个 IconButton（48dp 点击区）
2. 点「Aa」切换一个 Boolean 状态，弹出字号浮层（AnimatedVisibility + Slider）
3. 「换文件」移进「⋯」的 DropdownMenu
4. 栏高 56 → 52dp，底板 surfaceContainer + 顶部 1dp 发丝线
```

验收清单：

- [ ] 四个图标间距一致，垂直居中
- [ ] 点「Aa」浮层从底部滑出，拖动滑块正文实时重排
- [ ] 点浮层外任意处收起
- [ ] 点「⋯」能看到「换文件」并正常触发 SAF
- [ ] 阅读区可视高度比改前多 4dp
- [ ] 51 个单测仍全绿（UI 改动不应影响解析/搜索/高亮测试）

## 五、约束核对

| 约束 | 本方案如何满足 |
|---|---|
| 不引第三方 UI 库 | 只用已有 material3；图标手写 vector，**0 新增依赖** |
| 包体积敏感（1.18 MB） | 档位一 +8 KB，档位二 +2 KB，合计 **< 1.20 MB** |
| 51 个单测必须全绿 | 所有改动都在 `ui/` 层，解析/公式/目录/搜索/高亮的测试路径完全不变 |
| 不动已完成的逻辑 | 不改 `MdParser` / `Latex` / `SearchIndex` / `MdToc` / `CodeHighlighter` 一行 |
| 深浅色都要好看 | 每个新颜色（含语法高亮 6 色）都给出深/浅两套，验收时两种模式各看一遍 |

---

## 六、明确不做

- 换字体（内置字体已够用，引入字体会 +200 KB 起）
- 大量装饰性动效、骨架屏、粒子效果（阅读器应该安静）
- 重新设计信息架构（目录/搜索/设置的入口位置保持现状，只改外观）
- 引入 `material-icons-extended`（本轮图标需求小，手写更省）
